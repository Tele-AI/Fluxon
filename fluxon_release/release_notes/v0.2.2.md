# Fluxon v0.2.2

`v0.2.2` adds a minimal single-node path for exposing an existing local directory through an S3-compatible endpoint. It also establishes the `fluxon-py` PyPI distribution and aligns Python, Rust, Quick Start, wheel, and release metadata on one version.

## Release Summary

- Publish the Python distribution as `fluxon-py`; the import package remains `fluxon_py`.
- Publish the unified `fluxon_py-*.whl` through GitHub OIDC trusted publishing.
- Add `serve_s3_single_node(...)` for the minimal single-node FS/S3 composition.
- Map an existing local directory directly to a configurable S3 bucket; the default remains `quick-start-export`.
- Require first-login username and password replacement before S3 access is enabled.
- Publish the `fluxon_quick_start:0.2.2` image as a downloadable GitHub Release archive.

## Directory-Backed S3 Service

The exported local directory is the single source of truth. S3 writes become ordinary local files, and local file changes are visible through the S3 endpoint. Fluxon cache state remains rebuildable and does not become a second authoritative copy.

The new installed-package entrypoint accepts explicit KV master and KV owner runtime dictionaries:

```python
from fluxon_py.quick_start import serve_s3_single_node

serve_s3_single_node(
    "/path/to/data",
    "/path/to/state",
    kv_master_config=kv_master_config,
    kv_owner_config=kv_owner_config,
    export_name="local-data",
)
```

The helper reuses the canonical KV runtime process starters and does not introduce separate KV process wrappers.
`export_name` names both the Fluxon FS export and its S3 bucket; omitting it selects `quick-start-export`.

## Credential Bootstrap

New FS/S3 state starts with `admin / admin` only as bootstrap credentials. The first Web UI login must change both the username and password. Until that succeeds, S3 requests return `AccessDenied`; after the update, the bootstrap credentials are invalid and the completion state persists in `fs_master/access.db`.

## S3 Compatibility Scope

The gateway covers the core object workflow used by `rclone`, including bucket checks, object listing, `GET`, `HEAD`, single-range reads, `PUT`, `DELETE`, Multipart Upload, and header-based AWS Signature Version 4 authentication. Advanced AWS S3 features such as versioning, ACLs, lifecycle policies, and query-string presigned URLs remain outside the current scope.

## Distribution And Release Automation

Install from PyPI with:

```bash
python3 -m pip install --upgrade fluxon-py
```

PyPI normalizes the distribution wheel filename to `fluxon_py-*.whl`. Tag-push release runs publish that wheel through the GitHub `pypi` environment without a long-lived PyPI API token. Manual release rebuilds do not republish an existing PyPI file.

## Release Artifacts

- `fluxon_release.tar.gz`
  Contains the unified `fluxon_py` wheel and the packaged runtime support files.
- `fluxon_quick_start_0.2.2_docker_image.tar.gz`
  Contains the exported `fluxon_quick_start:0.2.2` image.

The current workflow publishes the Docker image as a GitHub Release archive; it does not push the image to Docker Hub or GHCR.
